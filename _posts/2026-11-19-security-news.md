## 1. 楽天証券：顧客情報が流出した可能性（最大約447万口座）

**何が起きたか**
楽天証券は11月17日、第三者によるアクセスを11月16日に把握して遮断・修正したと公表しました。調査で、11月11日にテスト環境内の情報が流出した可能性が判明したとしています。原因・侵入経路は調査中です。

**影響範囲**
- 最大約447万口座（退会者を含む）：支店・顧客コード、ログインID、氏名、生年月日、住所、電話番号、メールアドレス、勤務先、出金先口座情報、自己申告の年収・資産情報、商品別の保有状況、最終ログイン日。
- 最大約1,125万口座：顧客コードとログインIDのみ。

**現状と対応**
同社はパスワード・暗証番号の流出、およびこれに関連する不正アクセス・不正取引は確認されていないとしています。対象の顧客には個別に連絡するとしています。同社は、メールにURLを載せないこと、電話でログイン情報を尋ねないことを案内しています。

**やさしい解説**
証券会社の「お客様名簿」の写しが外に出たかもしれない状況です。鍵（パスワード）は盗まれていないとされますが、名簿には住所や資産の情報があるため、楽天証券を名乗る偽のメール・SMS・電話・郵便にだまされやすくなります。利用者は、不審な連絡のリンクは開かず公式アプリから確認し、パスキーを設定し、不安があれば取引や出金の一時停止設定を検討してください。なお、偽通知が増えるかどうかは推測であり、確認された事実ではありません。

**ソース**
- 楽天証券 発表：<https://www.rakuten-sec.co.jp/web/info/info20261117-02.html>
- Security NEXT（報道）：<https://www.security-next.com/193015>

## 2. Javaの Base64 デコーダの脆弱性「Java4Shell」（CVE-2026-114938）

**何が起きたか**
11月17日、CISAが即時のパッチ適用を呼びかけ、Oracleがパッチを公開しました。x86-64 HotSpotのAVX-512 VBMI最適化が施されたBase64デコーダに、範囲外書き込みの欠陥があります。発見者のCalifは、細工した入力でクラッシュし、条件次第で認証なしのリモートコード実行（RCE）が可能と説明しています。一方、他の研究者はクラッシュとメモリ漏えいまでを再現し、RCEは再現できていません。悪用は確認されていません（THN記事時点でCISAのKEV未登録）。

**影響範囲**
- 対象：Java 17.0.6以降、21、25、27、Java SE 8 Performance Pack、GraalVM。標準のJava 8/11は対象外です。
- AVX-512 VBMI対応CPU（Intel Ice Lake以降のXeon、AMD Zen 4以降）のみが対象で、ARM64は対象外です。
- Califは、Keycloak、Jira、Confluence、Artifactory、Jenkins、PingFederateなどが、アカウント不要で影響を受け得るとしています。
- CVSSは評価者でばらつきがあります（Calif 9.2（v4）、Oracle 8.1、Red Hat 暫定9.8）。

**現状と対応**
修正版は、Oracle Java SE 17.0.21.1／21.0.13.1／25.0.5.1／27.0.1.1です。Amazon CorrettoとAzul Zuluも提供しています。RHELやTemurinなどは、THN記事時点では未提供でした。暫定回避策はJVMオプション `-XX:-UseBASE64Intrinsics` で、再起動が必要です（パッチ適用後は外します）。

**やさしい解説**
多くのシステムの裏で動くJavaの「文字を変換する部品」に、特定のCPUでだけ使われる高速化部分の欠陥が見つかりました。細工したデータを受け取るとクラッシュし、最悪は乗っ取りにつながる可能性があります。ただし乗っ取りが実際に可能かは研究者の間で見解が割れており、その点は確定していません。IT担当者は、コンテナやアプライアンスに同梱されたJDKも含めて棚卸しし、インターネットに公開しているシステムから優先して更新してください。

- The Hacker News：<https://thehackernews.com/2026/11/java4shell-cve-2026-114938-enables-pre.html>

## 3. Puppet Enterprise / Puppet Server のRCEが悪用され、CISA KEVに追加（CVE-2026-115731）

**何が起きたか**
11月17日、CISAがCVE-2026-115731を悪用が確認された脆弱性（KEV）に追加しました。修正版は11月3日に公開済みです。レポート処理における信頼できないデータのデシリアライズの欠陥で、CA署名済みのエージェント証明書を持つクライアントが細工したレポートを送ると、サーバのサービスユーザー権限でコードを実行できます。CAが強い検証なしに自動署名している環境では、認証なしの攻撃者でも証明書を入手できる可能性があります。関連CVEはCVE-2026-115732で、CVSS v4は9.4です。

**影響範囲**
Puppet Enterprise 2026.0.0〜2026.0.1未満、2025.0.0〜2025.12.1未満、2023.8.0〜2023.8.13未満。Puppet Core 9.0.0〜9.1.3未満、8.22.2未満。OpenVoxも対象です。

**現状と対応**
修正版は、PE 2026.0.1／2025.12.1／2023.8.13、Puppet Core 9.1.3／8.22.2、OpenVox Server 9.2.0／8.18.0などです。米連邦機関の対応期限は12月1日とTHNが記載していますが、CISAのページでは未確認です。悪用の手口や標的は不明です。Neodymeは、サーバが侵害されるとCA署名鍵が奪われ、他のホストになりすまされる恐れがあると指摘しています。autosign設定の見直しと、証明書・ノードの点検を行ってください。

**やさしい解説**
Puppetは多数のサーバを一括管理する「司令塔」です。司令塔が乗っ取られると、配下のサーバ全体に影響が及びかねません。管理者は、まず修正版へ更新し、「身分証（証明書）を確認せず自動で発行する」設定になっていないかを確認してください。

**ソース**
- CISA：<https://www.cisa.gov/news-events/alerts/2026/11/17/cisa-adds-one-known-exploited-vulnerability-catalog>
- The Hacker News：<https://thehackernews.com/2026/11/hackers-exploiting-critical-puppet-rce.html>

## 4. NGINXのHTTP/2の脆弱性（CVE-2026-123007ほか）

**何が起きたか**
nginx.orgがセキュリティアドバイザリを公開しました（日付の記載なし）。THNは11月18日に報じています。1.9.5以降のHTTP/2フロー制御にメモリ破壊の欠陥があり、認証なしで、workerプロセスの権限でコードが実行される可能性があります。同時に、CVE-2026-123633、CVE-2026-121810、CVE-2026-113425、CVE-2026-123634（CVSS v4 9.2）も修正されました。研究者による解析とPoCの公開があります。悪用は、THN記事時点で報告されていません。

**影響範囲**
OSS版 1.9.5〜1.31.8、およびNGINX Plusです。

**現状と対応**
修正版は、1.31.9／1.30.7、NGINX Plus 37.3.0.1／37.0.8.1です。設定のreloadではなく、完全な再起動が必要です。暫定回避策の `http2 off;` は、一部（CVE-2026-123007・CVE-2026-123633）にのみ有効です。Ubuntu・Debianの修正パッケージは、記事時点で未配信でした。

**やさしい解説**
ウェブサーバの「受付窓口」にあたる部分の欠陥で、外部から細工された通信を送られると乗っ取りにつながる恐れがあります。ディストリビューションのパッケージを使っている場合は、配信状況を確認して更新し、更新後は必ず再起動してください。

## 5. Optimizely経由で大手サイトに不正スクリプトが配信された「OPTIMJACK」

**何が起きたか**
11月16日 04:21（UTC）頃から約16時間、攻撃者がOptimizely Webの顧客プロジェクトのJavaScript設定欄に不正コードを書き込み、CDN経由で各サイトの訪問者に配信しました。内容は、暗号資産アドレスのすり替え、カード情報の窃取、Cookieやスクリーンショットの送出、一部のiPhone/iPad向けエクスプロイトの配信です。

**影響範囲**
StepSecurityは、報道機関、SaaS、金融、小売などの178組織に影響したと報告しています。ただし、件数は178組織／186サイト／188スクリプトとソースによって異なります。

**現状と対応**
Optimizelyは、脆弱性（報道ではアカウント登録フローとされる）を修正し、注入されたコードを削除し、トークンの失効と顧客への通知を実施したと説明しています。Optimizelyの公式声明は直接確認できていません。感染サイトは11月16日中にほぼ解消したとされます。iOS端末が実際に侵害されたかは不明です。

**やさしい解説**
多くのサイトが共通で使っている「外部の部品」に細工をされたため、サイト自体が破られていなくても訪問者が被害を受ける状態でした。11月16日に大手サイトでカード情報を入力したり、暗号資産のアドレスをコピーして貼り付けたりした人は、明細や送金先を確認し、iOSを最新にしてください。Optimizely利用企業は、プロジェクトのJavaScript、ユーザー、APIトークンを点検し、決済ページの第三者タグを減らしてください。

**ソース**

- Risky Bulletin：<https://news.risky.biz/risky-bulletin-hackers-hijack-optimizely-to-deliver-malware-on-178-popular-sites>

## 6. Microsoft「agent-framework」PyPIパッケージに認証情報窃取コード

**何が起きたか**
11月17日、`agent-framework` の1.26.1と1.26.2がPyPIに公開されました。Pythonの起動のたびに実行される仕組みで、環境変数、クラウドやパッケージ管理の認証情報、AzureやGitHub Actionsのトークンなどを外部へ送信するものでした。公開権限の奪取経路は不明で、Microsoftの公式声明は未確認です。

**影響範囲**
月間約19万ダウンロードのパッケージです。露出は11月17日 20:35〜21:20（UTC）頃とTHNは伝えています。

**現状と対応**
両バージョンとも隔離済みで、最後の安全版は1.26.0です。該当時間帯に導入した環境は隔離し、認証情報をローテーションし、Azureのサインインログを点検してください。

**やさしい解説**
正規の名前のパッケージに「合鍵を盗む仕掛け」が混ざった形です。インストールしただけで動くため、該当時間帯に入れた環境では、保管していた鍵やトークンを全て作り直すのが安全です。なお、本件は単一ソース（THN）のみの情報です。

**ソース**
- The Hacker News（単一ソース）：<https://thehackernews.com/2026/11/attackers-compromise-microsofts-agent.html>

## 8. Apache Rollerの認証不要RCEが悪用される（CVE-2026-129448）

**何が起きたか**
THNが11月18日に報じました（ASFの発表を引用）。XML-RPCエンドポイントが、認証前にデシリアライズ処理を行う欠陥です。ASFは悪用を確認したと説明していますが、手口は非公開です。CVSSは9.8で、9月に修正されたCVE-2026-82384の修正が不完全だった件と関連します。

**影響範囲**
Apache Roller 4.0.0〜6.1.4が対象です。

**現状と対応**
修正版は6.1.6以降です。暫定対応は、XML-RPCサーブレットのマッピングの無効化などです（管理画面での無効化では不十分とされています）。CISAのKEVに掲載されているかは未確認です。

**やさしい解説**
ブログシステムの「外部から呼び出す窓口」が、本人確認の前にデータを処理してしまう欠陥です。Rollerを運用している場合は、早急に更新するか、この窓口を設定ファイル側で止めてください。
