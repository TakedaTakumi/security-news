## 1. ENEOS 公式アプリに不正アクセス、サービスを停止

**何が起きたか**
ENEOS は11月25日、公式アプリへの第三者による不正アクセスを検知したと公表しました。同日16時ごろからアプリを停止しています。被害の拡大を防ぎ、情報が漏れたかどうかを確認するための措置です。

**影響範囲**
- モバイル EneKey とアプリ内クーポンが使えません。
- サービスステーション（SS）は通常どおり営業しています。燃料の供給に影響はありません。
- 漏えいの有無・件数・手口・時期は調査中です。
- 報道によると、アプリの会員数は約2,100万人です。これは被害人数ではありません。

**現状と対応**
- 再開時期は未定です。
- 支払いは、現金、クレジットカード、タグ型 EneKey で行えます。
- ENEOS を装うメールや SMS の URL・添付ファイルは開かないでください。ID やパスワードも入力しないでください。

**やさしい解説**
お店の会員証の発行窓口に怪しい人が入ったため、念のため窓口を閉めている状況です。給油はこれまでどおりできます。まだ「情報が漏れた」とは言えません。便乗した偽メールや偽 SMS が届くことがあるので、リンクは開かず、公式アプリや公式サイトから確認してください。

**ソース**
- ENEOS（11月25日）：<https://www.eneos.co.jp/announcement/20261125.html>
- Security NEXT：<https://www.security-next.com/193377>
- SBbit：<https://www.sbbit.jp/article/cont1/188774>

## 2. 【続報】Drupal 本体に追加の欠陥（CVE-2026-136716）、悪用を確認

**何が起きたか**
Drupal は11月25日、SA-CORE-2026-019 を公表しました。11月20日に修正された Fail2Install（CVE-2026-132165、SA-CORE-2026-017）の後も、乗っ取られる余地が残っていたという内容です。インストーラが不完全な状態や特殊な状態にあるサイトが対象です。Drupal は、実際に悪用されていると明記しています。

**影響範囲**
- 深刻度は「Highly critical」（21/25）です。CVSS の数値は記載されていません。
- 本番サイトも対象です。
- 対象バージョンは次のとおりです。
  - 10.6.23 未満
  - 11.0.0 以上 11.3.23 未満
  - 11.4.0 以上 11.4.14 未満
- StepSecurity の推計では、公開されている Drupal サイトは約55,800です。うち約31,500が影響を受けるブランチです（The Hacker News 経由）。

**現状と対応**
- 修正版は 11.4.14、11.3.23、10.6.23 です。修正後に update.php の実行が必要です。
- サポートが終わった版（11.0〜11.2、10.5以前）には、修正が出ません。
- ログで、ユーザー1（最初の管理者）に関する変更がないか確認してください。
- ユーザー1のメールアドレスを自分の管理下に置き、パスワードのリセットも検討してください。
- CISA の KEV への追加の有無は、確認できていません。

**やさしい解説**
先日直した「工事用の入口」に、まだ別の鍵のかかっていない扉が見つかった状況です。しかも、すでに誰かが使っています。Drupal でサイトを運営している担当者は、更新して update.php を実行し、管理者アカウントに見覚えのない変更がないか確認してください。サイトを見るだけの利用者が行う作業はありません。

**ソース**

- The Hacker News：<https://thehackernews.com/2026/11/drupal-warns-of-new-highly-critical.html>

## 3. 1Password、従業員の GitHub アカウント侵害で一部顧客のアカウント情報が流出

**何が起きたか**
1Password は11月25日、セキュリティインシデントを公表しました。11月19日に、従業員の社内 GitHub アカウントが侵害された兆候を見つけ、調査を始めたとしています。攻撃者は、次のことをしたと説明されています。

- ソースコードにアクセスし、非公開リポジトリをコピーした。
- CI/CD（自動ビルド・配布の仕組み）にアクセスした。
- バックエンドに悪意あるコードを入れ、一部顧客のアカウント記録をダウンロードした。

**影響範囲**
- 件数は公表されていません。
- 流出した項目は次のとおりです。
  - 名前、サインイン用のメールアドレス
  - アカウント ID・ユーザー ID
  - 作成日時・最終サインイン日時
  - 公開鍵、SRP（パスワード認証方式）のパラメータ
  - 招待・プロビジョニング・復旧メールのリンクに含まれるトークンの一部
  - 内部構成に関する、秘密ではないメタデータ
- 保管庫の中身、鍵、アカウントパスワード、Secret Key、復旧キー、アプリ・拡張機能は、影響を受けていないと説明しています。

**現状と対応**
- 1Password は次の対応をしたとしています。
  - 侵害されたアカウントの無効化、トークンの失効、認証情報の更新
  - CI/CD のインフラの秘密情報の更新
  - サービスをクリーンな版へ切り替え
  - 招待・復旧コードを、6桁の数字から10文字の英数字へ変更
- トークンだけではログインできません。SSO か6桁コードが別途必要です。アカウントが乗っ取られた証拠はないとしています。
- 原因分析（RCA）は、数週間以内に公表される予定です。
- 1Password は、利用者の対応は不要としています。
- 侵害の経路と攻撃者は、まだ分かっていません。

**やさしい解説**
鍵そのものは盗まれていませんが、顧客名簿の一部と、受付で使う引換券の断片が持ち出された状況です。引換券の断片だけでは入れない仕組みと説明されています。それでも、1Password を名乗る予期しない招待・復旧のメール、SMS、電話には注意してください。Secret Key は、公式アプリか、自分で URL を入力した公式サイトにだけ入力しましょう。

## 5. 【続報】Mitel MiCollab はゼロデイとして悪用されていた（Accenture 報告）

**何が起きたか**
CISA は11月25日、KEV に10件を追加しました（Danfoss 3件、Juniper 1件、Mitel 5件、Vates 1件）。翌26日、SecurityWeek が Accenture Apex Labs の分析を報じました。本サイトは、Mitel の5件を11月26日に取り上げています。今回の新しい事実は次のとおりです。

- Mitel の公表（11月16日）より前の11月15日に、被害組織にウェブシェル（遠隔操作用の不正な仕掛け）が置かれました。ゼロデイ（修正前）の悪用です。
- 侵入から約12分でコマンドを実行し、約30分で最高権限（root）を得ました。約20時間で、内部のバックアップサーバとデータベースサーバに届きました。
- AD（社内の ID 管理）と連携する ID 基盤にも届き、機密情報が盗まれました。
- 攻撃側のインフラが、商用 AI の API 2サービスと通信していました。AI の使い方は、Accenture も断定していません。
- 2件目の組織は、11月9日から同じインフラと通信していました。侵入経路は不明です。
- 既知の攻撃グループとの関連は見つかっていません。

**影響範囲**
- 対象 CVE は、CVE-2026-133275、-133303、-133311、-133323、-133324 です。認証なしで悪用できる複数の欠陥です。
- 米連邦機関の対応期限は、SecurityWeek によると4件が11月28日、1件が12月9日です。CISA のページでは確認できていません。

**現状と対応**
- パッチを適用してください。
- パッチ前に侵入されていた場合に備え、痕跡を確認してください。
- 製品の外部公開を制限してください。
- AD 連携の認証情報を見直してください。

**やさしい解説**
鍵が配られる前から、誰かが合鍵で出入りしていた状況です。パッチを当てるだけでは、すでに入った相手は追い出せません。Mitel MiCollab を使っている担当者は、更新に加えて、過去の記録に不審な動きがないかを確認してください。一般の利用者が行う作業はありません。

## 6. Todoist、盗まれた認証情報から本番環境へ侵入され、一部ユーザー情報が取得される

**何が起きたか**
タスク管理サービス Todoist は、セキュリティインシデントを公表しました。初回の告知は11月24日（UTC、日本時間11月25日未明）です。11月25日に影響を受けたユーザーへの通知を終え、11月26日には影響のないアカウントにも、予防的なパスワードリセットのメールを送りました。告知も更新されています。

攻撃の流れは、次のとおりです（11月22〜23日）。
1. 盗まれた版管理システムの認証情報で、自動化ワークフローを変更した。
2. 追加の認証情報を取得した。
3. 従業員のアカウントを乗っ取った。
4. クラウド基盤に入り、11月23日に本番システムで顧客情報の一部を取得した。

アプリのコードが変更された形跡は確認されていません。最初の認証情報をどう入手されたかは、確認できていません。

**影響範囲**
件数は公表されず、割合だけが示されています。
- 約6%：旧ハッシュ方式の古いアカウントです。メールアドレス、ソルト付き SHA1 のパスワードハッシュ、作成日が対象です。ログインの形跡はありません。
- 約0.003%：API トークンと Slack 連携トークンです。一部で、プロジェクトなどが読まれました。
- 約0.001%：認証情報に似た語の検索結果です。
- 約0.001%：Outlook 連携のユーザーです。メールの件名、送信者、本文の先頭255文字、添付ファイルのメタデータが対象です。

**現状と対応**
- 影響を受けたアカウントのパスワードを無効にしました。
- API トークンの失効、OAuth の切断、Outlook アドインの無効化、Slack トークンの失効も行いました。
- Todoist からのメールを確認し、案内に従ってください。
- 他のサービスとのパスワードの使い回しはやめてください。
- Todoist に書いた秘密情報（API キー、復旧フレーズなど）は、失効させて再発行してください。

**やさしい解説**
社員の通行証が盗まれ、そこから順に奥の部屋まで入られた状況です。パスワードは「ハッシュ」という形で保管されていますが、古い方式のものは、解読されやすくなります。割合は小さくても、自分が対象かもしれないので、届いたメールを確認してください。メモ代わりに秘密の情報を書いていた人は、その情報を作り直してください。

**ソース**
- Todoist ヘルプ（セキュリティインシデント）：<https://www.todoist.com/help/todoist/get-started/security-incident-in-november-2026-cG0EIACNU>
- The Hacker News（ThreatsDay）：<https://thehackernews.com/2026/11/threatsday-250-rogue-extensions-10m.html>

## 7. 【続報】PAN-OS に Fragnesia（CVE-2026-46300）の修正版

**何が起きたか**
Palo Alto Networks が、PAN-SA-2026-0015 を公表しました。Linux カーネル由来の権限昇格の欠陥 Fragnesia（CVE-2026-46300）に対する、PAN-OS の修正版です。日付は、ヘッダーが11月25日、タイムラインの初回が11月24日で、食い違っています。

**影響範囲**
- 悪用は、次の連鎖とされています。
  1. PHP2Shell（CVE-2026-109618）で、公開された管理画面から侵入する。
  2. Fragnesia で root 権限を得る。
  3. ウェブシェルを置く。
- Dream の報告では、25台が侵害されたとされます（SecurityWeek 経由）。

**現状と対応**
- 修正版の例は、12.2.4-h3、12.1.10-h6、11.2.16-h3、11.1.16-h6、10.2.18-h15 などです。全リストはアドバイザリを参照してください。
- Palo Alto は、PHP2Shell の修正済みの機器は、既知の経路から保護されるとしています。
- 更新し、管理画面をインターネットに公開しないでください。

**やさしい解説**
会社のネットワークの入口を守る機器の「管理用の裏口」が、外から見える状態だと危険です。裏口から入られたうえ、機器の中で最高権限まで取られるおそれがあります。PAN-OS の担当者は、更新と、管理画面の公開停止を行ってください。

**ソース**
- Palo Alto Networks：<https://security.paloaltonetworks.com/PAN-SA-2026-0015>
- SecurityWeek：<https://www.securityweek.com/palo-alto-networks-patches-fragnesia-flaw-used-to-root-firewalls/>

## 8. PolinRider：北朝鮮系とみられる攻撃者が GitHub リポジトリに不正コード

**何が起きたか**
The Hacker News が11月26日に報じました。攻撃者は、乗っ取った開発者アカウントで過去のコミット履歴を書き換え、Python のユーティリティや conftest.py に、読み込み用のコード（ローダー）を隠します。命令の取得先をブロックチェーンに置くため、止めにくい手口です。最新の波では、VS Code でフォルダを開くだけで動きます。入口は、偽の採用面接・課題や、乗っ取られた管理者アカウントです。

**影響範囲**
- 研究者によって、規模の推計に差があります。
  - Apiiro の推計：少なくとも7,609リポジトリ、2,330アカウント
  - SafeDep の確認：375リポジトリ、260アカウント
- PyPI や npm を通じた配布は、見つかっていません。
- 狙われるのは、秘密情報、ブラウザのパスワードと Cookie、暗号資産です。
- 北朝鮮との関連は、研究者の評価です。

**現状と対応**
- 見覚えのない Python ファイルや、force push（履歴の強制上書き）がないか確認してください。
- トークンを更新してください。
- 採用課題を名乗るプロジェクトは、実行しないでください。
- VS Code の自動実行タスクを無効にしてください。

**やさしい解説**
開発者仲間のふりをして、「この宿題をやってみて」と罠入りの荷物を渡す手口です。開いただけで動く場合があるので、知らない人から届いたプロジェクトは、安全な環境以外では開かないでください。自分のリポジトリにも、覚えのない変更が混ざっていないか確かめましょう。

**ソース**
- The Hacker News：<https://thehackernews.com/2026/11/north-korea-linked-polinrider-poisons.html>
- SafeDep（研究者報告、未直接確認）：<https://safedep.io/blog/polinrider-python-loader-ethereum-calldata>
- Apiiro（研究者報告、未直接確認）：<https://apiiro.com/blog/polinrider-north-korea-worm-forged-github-commits>

**やさしい解説（この節の全体）**
会社の裏方のシステムや、機器の管理画面が狙われる点は共通しています。利用者としては、各社の公式発表を確認し、名前をかたる不審なメールや SMS のリンクを開かないことが基本です。担当者は、更新が出ている製品を早めに更新し、更新が出ていない機器は外部に公開しないでください。
