## 1. SAP、GitHub 上の開発環境への不正アクセスを認める

**何が起きたか**
SAP は、社内 IT 環境で不審な活動を確認し、顧客を守るための措置を取ったと認めました。ドイツの Der Spiegel は、社内向けの通知を根拠に、従業員の認証トークンが盗まれたと報じています。攻撃者はそのトークンで、GitHub 上のソースコードをコピー・変更したとされます。報道は11月26日（現地）から始まり、BleepingComputer と SecurityWeek が11月27日に伝えました。

**影響範囲**
- GitHub 上のコードが対象です。SAP は GitHub で、開発者向けツールやサンプル、オープンソースを公開しています。
- 社内の秘密のコードに届いたかどうかは、はっきりしていません。
- 顧客に届く成果物に改ざんされたコードが入った、という報道は見当たりません。
- Handelsblatt は、SAP が署名鍵を入れ替え、GitHub へのアクセスを制限し、自動化された開発作業を止めたと報じています（報道ベース）。
- 攻撃に AI が使われた可能性が、情報筋の話として報じられています。これは未確認です。

**現状と対応**
- SAP は、調査したかぎり、顧客の業務データへの不正アクセスの証拠はないと説明しています。
- 顧客システムへの波及を示す証拠も、現時点ではないとしています。
- どの環境が影響を受けたか、GitHub から取得している顧客が何かをすべきかは、SAP は明らかにしていません。
- 利用企業は、SAP からの案内を確認してください。

**やさしい解説**
部品メーカーの設計図の保管庫に、社員の入館証を盗んだ人が入った状況です。完成品に不良が混ぜられたという話は、今のところありません。ただし、設計図が書き換えられたかどうかの確認が続いています。SAP の製品を使う会社の担当者は、SAP の公式な案内を待ち、GitHub から入手した SAP 製のコードを使っている場合は、取得元と版を確認してください。

## 2. pCloud Pass（パスワード管理）が攻撃を受けたと認める

**何が起きたか**
pCloud のパスワード管理サービス「pCloud Pass」の利用者に、新しい端末が接続されたという通知が届きました。2段階認証を使っていても届いたとの報告があります。pCloud は、Pass への攻撃を認めました。攻撃は「すぐに封じ込めた」としています。BleepingComputer が11月27日に報じました。

**影響範囲**
- pCloud によると、一部の Pass 利用者のメールアドレスが露出し、ログインの試行がありました。件数は公表されていません。
- クラウドストレージ本体は影響を受けていないとしています。
- 保管されたパスワードとメモは端末内で暗号化されており、マスターパスワードがないと開けないと説明しています。
- 暗号化された保管庫が持ち出されたかどうかは、pCloud は明らかにしていません。
- 通知メールの「設定を開く」のリンクが、QA 環境とみられるホスト名を指していました。BleepingComputer が確認しています。
- 利用者の報告は、掲示板（Reddit）の投稿が根拠です。pCloud の声明も、BleepingComputer が掲示板の投稿から引用したものです。

**現状と対応**
- 身に覚えのない端末の通知が届いたら、送信元とリンク先を確かめてください。
- pCloud は、マスターパスワードや復旧用の単語を、メール・電話・チャットで尋ねることはないと説明しています。
- マスターパスワードは、他で使っていない強いものにしてください。

**やさしい解説**
金庫の鍵（マスターパスワード）は盗まれていないとされますが、金庫の中身が持ち出されたかどうかは、まだ言えない状況です。持ち出されていた場合は、マスターパスワードが弱いと、時間をかけて破られるおそれがあります。pCloud Pass の利用者は、マスターパスワードの強さを見直しましょう。通知メールのリンクは開かず、公式アプリから確認してください。

**ソース**
- BleepingComputer：<https://www.bleepingcomputer.com/news/security/pcloud-confirms-password-manager-hack-after-suspicious-login-alerts/>
- pCloud の声明は、Reddit のコメントとして掲載されています（BleepingComputer が引用、直接は未確認）。

## 3. 公式サイトの Q-Dir と DesktopOK のインストーラが改ざん、遠隔操作マルウェアを配布

**何が起きたか**
Windows 向けの Q-Dir と DesktopOK を配布する公式サイト（SoftwareOK）で、インストーラが改ざんされていました。韓国の AhnLab が、11月26日に分析を公開しています。実行すると、本物のプログラムも動かしつつ、外部から Python 製の遠隔操作マルウェア（RAT）を入れる仕組みです。

**影響範囲**
- 確認された改ざん版は次のとおりです。
  - Q-Dir 12.85.0.0、12.84.0.0、12.83.0.0
  - DesktopOK 12.85.0.0、12.82.0.0
- 公式の配布ページでの直接ダウンロードと、導入済みソフトの更新の両方で、改ざん版が配られました。
- 被害者数、改ざんの方法、改ざんの期間は、確認されていません。
- 攻撃者は特定されていません。

**現状と対応**
- ダウンロードしたファイルの SHA-256 ハッシュを、公式ページの値と照合してください。
- 入れ直しだけでは、すでに入った RAT は消えません。
- 次のような痕跡を確認してください。
  - 見覚えのない Python 環境
  - Microsoft Edge を装った、スケジュールされたタスク
  - 不審な外部通信
- ウイルス対策ソフトを更新し、フルスキャンを行ってください。
- 感染を確認した場合は、ネットワークから切り離してください。

**やさしい解説**
いつも買い物をしている公式の店に並ぶ商品に、毒が混ぜられた状況です。店が公式であっても、安全とは限りません。対象の版を入れた人は、ファイルの照合と、パソコンの確認をしてください。個人のパソコンで感染が疑われる場合は、重要なアカウントのパスワードを、別の安全な端末から変更しましょう。

**ソース**
- AhnLab ASEC：<https://asec.ahnlab.com/en/96827/>
- The Hacker News：<https://thehackernews.com/2026/11/hackers-trojanize-official-q-dir-and.html>

## 4. 監視ツール Cacti に、修正版のないゼロデイ（公開済み PoC）

**何が起きたか**
ネットワーク監視ツール Cacti に、ゲストアカウントが有効な場合に、遠隔からコマンドを実行されるおそれのある欠陥が見つかりました。研究者が、事前に Cacti 側へ報告しないまま、概念実証（PoC）を GitHub に公開しています。watchTowr が11月26日（UTC）に FAQ を公開しました。The Hacker News と BleepingComputer が11月27日に報じています。

**影響範囲**
- 確認された対象は Cacti Core 1.2.31 です。それ以前の版が影響を受けるかは、確認されていません。
- ゲストアカウントが有効な場合に限られます。ゲストアカウントは、Cacti 0.8.7 以降、初期設定では無効です。
- CVE は、未割り当てです。
- 実際に悪用された報告は、11月27日の時点ではありません。
- 実行されるのは、Web サーバ・ポーラーのアカウントの権限です。多くの場合、root ではありません。

**現状と対応**
- 修正版はありません。Cacti 側の対応も、確認できていません。
- ゲストアカウントを無効にしてください。
- 管理画面へのアクセスを、信頼できる内部のネットワークに限ってください。
- ポーラーの設定に、見覚えのないコマンドが入っていないか確認してください。
- 修正版が出たら、すぐに更新してください。

**やさしい解説**
社内の「機器の見張り番」の画面に、来客用の鍵が付いたままの状態です。その鍵を使うと、見張り番の持つ機器の接続情報まで触れるおそれがあります。Cacti を使っている担当者は、ゲストアカウントを無効にして、画面を社外に公開しないようにしてください。

**ソース**
- watchTowr：<https://watchtowr.com/intelligence/4http2root-cacti-zero-day-faq/>
- The Hacker News：<https://thehackernews.com/2026/11/unpatched-cacti-zero-day-enables-rce-in.html>
- BleepingComputer：<https://www.bleepingcomputer.com/news/security/unpatched-cacti-zero-day-with-public-poc-gives-remote-code-execution/>

## 5. Linux カーネルの NFS サーバに、遠隔から root を取られる欠陥「NFS2ROOT」（CVE-2026-99362）

**何が起きたか**
Linux カーネルの NFS サーバ（nfsd）に、ヒープバッファオーバーフローの欠陥が見つかりました。OpenSec が「NFS2ROOT」と名付けています。認証なしで、遠隔から root 権限を取られるおそれがあります。BleepingComputer が11月27日に報じました。

**影響範囲**
- 対象は、次の版より古いカーネルです。
  - 6.12.117
  - 6.18.61
  - 7.3.2
  - 7.4-rc1
- 欠陥は、Linux 3.16（2014年）から存在していたとされます。
- NFS サーバ（NFSv4.1 または 4.2）が動いていて、TCP 2049 番がインターネットから届く場合が対象です。
- 悪用の報告は、記事の時点ではありません。

**現状と対応**
- 修正は8月に提出されています（BleepingComputer 経由）。
- ディストリビューションの最新のカーネルに更新して、再起動してください。
- NFS を使っていなければ、nfs-server を止めてください。
- 使っている場合は、2049 番を、信頼できるクライアントだけに限ってください。

**やさしい解説**
社内のファイル共有の「受付」に、外から入れる穴がある状況です。共有サーバを、インターネットから直接見える形にしていなければ、危険はかなり小さくなります。担当者は、更新と、2049 番を外に公開していないかの確認をしてください。

**ソース**
- BleepingComputer：<https://www.bleepingcomputer.com/news/security/new-nfs2root-linux-flaw-can-let-attackers-gain-root-privileges/>
- OpenSec（BleepingComputer 経由。アクセス時に HTTP 403 のため直接は未確認）：<https://opensec.in/blog/nfs2root-cve-2026-99362>

## 6. 米コロラド州の公式アプリ myColorado、約10万人分の書類が閲覧された可能性

**何が起きたか**
コロラド州の公式アプリ「myColorado」が攻撃を受け、利用者が保存した書類が閲覧されました。州の情報技術局（OIT）は、AWS 環境で、攻撃が自動の検知を作動させたことで気づいたと説明しています。アプリは先週から停止中で、再開の時期は決まっていません。SecurityWeek が11月27日に報じました。

**影響範囲**
- 約10万人が対象の可能性があります。利用者全体は約210万人です。件数は、今後見直される可能性があります。
- 対象は、「myCards and Documents」に保存された、政府発行の身分証・車両登録証・保険証の画像や PDF です。

**現状と対応**
- 州は、11月27日から、対象者への個別の連絡を始める予定です。
- 再開の前に、安全対策を強化するとしています。

**やさしい解説**
アプリは、免許証などのスマホ内の控えを、クラウドに預ける作りです。その預かり所に、侵入された状況です。州の通知が届いたら、案内を確認し、免許証などの再発行や、悪用への備えを検討してください。日本の利用者への直接の影響は小さいとみられます。

**一般利用者向け**
