# 毎朝のタスク：「今日のホットニュース」作成手順

このリポジトリは、ウェブサービスの脆弱性・情報流出に関するニュースを毎朝まとめ、
GitHub Pages（Jekyll）で公開するためのものです。
定期実行（毎日 9:00 JST）で起動されたら、以下の手順を**確認を求めずに最後まで**実行してください。

---

## 0. 前提

- 本日の日付は必ず日本時間で取得する：`TZ=Asia/Tokyo date +%Y-%m-%d`
- 対象期間：実行時点から**直近48時間**に公表・報道されたもの
- 対象範囲：日本国内外を問わない
- 出力言語：すべて日本語
- 同じ日付の記事が `_posts/` に既にある場合は、新規作成せずにその日の作業を終了する（二重実行対策）

## 1. 掲載済み台帳を読む

- `_data/covered.yml` を読み、過去に掲載した案件（id / タイトル / キーワード / CVE）を把握する

## 2. 情報を広く収集する

- 極力、一次ソースを参照する
  - 例：被害企業・運営者の公式発表、ベンダーのセキュリティアドバイザリ、CVE/NVD、CISA KEV、JPCERT/CC、IPA、JVN、個人情報保護委員会、各国当局
- 二次以降のソース（報道機関・セキュリティ専門メディア等）も、参照数が多ければ採用してよい
  - 例：BleepingComputer, The Record, SecurityWeek, The Hacker News, Krebs on Security, ITmedia, Publickey, Security NEXT, 日経クロステック

## 3. 真偽を確認する

- 複数ソースでの裏付け、一次ソースとの照合を行う
- 公表日・報道日が直近48時間以内かを確認する
- 未確認情報・推測は「未確認」と明示して区別する

## 4. 重複判定（再掲ルール）

- 台帳にある案件は、**新しい事実（続報）がある場合のみ**掲載する。見出しに【続報】を付け、新しい事実を中心に書く
- 新しい事実がない既出案件は掲載しない
- 判定に迷う場合は、CVE番号・企業名・サービス名で台帳と突き合わせる

## 5. 記事を作成する

ファイル：`_posts/YYYY-MM-DD-security-news.md`（日付は日本時間）

```markdown
---
layout: post
title: "今日のホットニュース（YYYY年M月D日）"
date: YYYY-MM-DD 09:00:00 +0900
---
```

本文の構成：

1. **今日のポイント**（3行程度の要約）
2. **ニュース本文**（重要度・影響の大きい順）。各ニュースに以下を記載する
   - 何が起きたか
   - 影響範囲（件数・対象サービス・対象バージョン等）
   - 現状と対応（パッチ、利用者が取るべき行動）
   - **やさしい解説**（専門用語をかみくだき、身近なたとえと「利用者として何をすればよいか」を書く）
   - **ソース**（URLを必ず併記。一次ソースを先に書く）
3. **今日やること**（一般利用者向け／IT担当者向け）
4. **留意点**（未確認情報、検証の限界、期間外として見送った案件）

掲載すべき新規ニュースが1件もない日は、「本日は新規・続報ともに重大なニュースはありませんでした」と書いた短い記事を作成する。

## 6. 検証する

- 事実関係・日付・数値・リンクを再確認し、誤りがあれば修正する
- 確証が得られなかった点は、その旨を本文に明記する

## 7. 台帳を更新する

`_data/covered.yml` に、掲載した案件を追記・更新する。

```yaml
- id: 英小文字とハイフンの一意なID（例: piccoma-blastmail-2026-10）
  title: 案件名
  first_reported: YYYY-MM-DD   # 初めて掲載した日
  last_updated: YYYY-MM-DD     # 最後に掲載した日（続報で更新）
  keywords: [企業名, サービス名, 通称]
  cves: [CVE-XXXX-XXXXX]       # なければ []
  posts: [YYYY-MM-DD]          # 掲載した記事の日付
```

続報の場合は新規追加せず、既存エントリの `last_updated` と `posts` を更新する。

## 8. コミットして公開する

```bash
git add _posts _data
git commit -m "news: YYYY-MM-DD"
git push origin main
```

- main への push が拒否された場合は、`claude/news-YYYY-MM-DD` ブランチに push し、その旨をセッションの最後に報告する

---

## 守るべきルール（公開サイトのため必須）

- **記事本文を転載しない**。自分の言葉で要約し、詳細はリンク先に誘導する
- 原文の引用は必要最小限にする（1ソースにつき1回、短いフレーズのみ）
- 出典のない主張を書かない。出典元を推測で作らない
- 個人を特定・中傷する内容を書かない
- 攻撃手法の具体的な再現手順や、悪用コードを掲載しない
